# ADR-030 — بصمةُ كلمة المرور الجديدة بصيغة PBKDF2 وحدها لغير مدير النظام (تصليب · المراجعة المعمارية KIVO_262)
- الحالة: معتمد · 2026-10-12 (KIVO_262)
- السياق: المراجعةُ المعمارية وجدت تشفيرَ كلمة المرور مكرّراً بين الواجهة (`src/auth/330-auth.js`) والخادم (`workers/parts/052-aud-events.js`) بصيغتين متوافقتين،
  لكنّ الخادم كان يخزّن أيَّ نصٍّ يرسله المدير بصمةً لحساب موظفه — فعميلٌ قديمٌ أو معدَّل يستطيع تخفيضها إلى djb2 القديمة (`p1$`) أو نصٍّ اعتباطي.
- القرار: `phNewOk` في `usersRule` و`enfUsersWrite`: البصمةُ **الجديدة أو المتغيّرة** من غير مدير النظام = `p2$<iter>$<salt32hex>$<hash64hex>` بعدد تكراراتٍ
  بين `PBKDF2_ITER` و`PBKDF2_MAX` — والبصمةُ القائمةُ دون تغيير تمرّ (بياناتٌ قديمة) · مديرُ النظام مستثنى (استعادةُ نسخٍ قديمة تحمل `p1$`) · رسالةُ رفضٍ عربية `ph`.
- البدائل المرفوضة: إلغاءُ تشفير الواجهة ونقلُه للخادم (تغييرُ بروتوكول الحفظ — خارج النطاق الآن) · رفضُ `p1$` لمدير النظام (يكسر الاستعادة).
- النتائج: لا تخفيضَ صامت · الواجهةُ الحقيقية تكتب `p2$` دائماً (WebCrypto) · عُدّةُ `cfbench/hard.mjs` كُيّفت لبصمةٍ حديثة مع توكيدٍ جديد للرفض (معلن).
- الأدلة: `tests/unit/ph_downgrade.test.mjs` · `cfbench/hard.mjs` (94/0).
