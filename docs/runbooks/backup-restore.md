# Runbook — النسخ والتحقق والاستعادة لقاعدة Preview

الأدوات مقيدة بقاعدة `bassam-db-preview` ومعرّفها `9b671cce-2bf3-46e9-84b5-23645227f0e0` في الحساب المعتمد. لا تتيح أعلام البيئة القديمة الوصول إلى Production. سلامة الربط لا تمنح إذنًا بتصدير البيانات أو تنفيذ استعادة مدمرة؛ راجع العملية ونطاق فقد الكتابات اللاحقة أولًا.

| الأداة | الوظيفة والحدود |
|---|---|
| `backup.sh bassam-db-preview [private-output-directory]` | تصدير كامل إلى SQL مع بصمة وmanifest؛ يتطلب وجهة خاصة معتمدة ومراجعة محتوى البيانات. ليس خطوة تلقائية في أداة الاستعادة. |
| `verify.py <dump.sql> [--manifest f.json] [--expect-tables …]` | تحقق محلي باستخدام SQLite مع فحص العلاقات؛ لا اتصال سحابي. قد يتضمن manifest تفاصيل بيانات، فتطبق عليه حماية النسخة نفسها. |
| `verify.py --diff a.sql b.sql` | مقارنة نسختين محليتين دون تغييرهما. |
| `snapshot_local.py <db.sqlite> <out.sql>` | إنشاء نسخة SQL من قاعدة محلية للاختبار، مع ترتيب علاقات الجداول. |
| `restore.sh bassam-db-preview --bookmark … --review … --evidence-dir … --yes` | استعادة Time Travel إلى نقطة مراجعة ثم فحص المخطط والسجل والتصريح. لا تصدير ولا إسقاط جداول أو إعادة تشغيل dump ولا تعديل Pages أو R2. |

تحتاج أداة الاستعادة Python 3.11+ وNode وحزمة Wrangler **4.156.0** المحلية التي روجع فيها عقد الاعتماد والسجلات. يستخدم `KIVO_PYTHON` و`KIVO_NODE` المفسرين الموجودين، ويمكن تحديد `KIVO_WRANGLER_JS` بمسار `bin/wrangler.js` المطلق للحزمة المثبتة. لا تثبيت تلقائيًا ولا تشغيل لشيم `.cmd` أو أمر shell؛ اختلاف إصدار Wrangler يحتاج مراجعة جديدة. يبقى اعتماد `auth token --json` في الذاكرة فقط، مع تعطيل كتابة سجلات Wrangler.

## قبل الترحيل

1. تحقق من المشروع والفرع وربط D1 الفعلي؛ اسم Preview وحده غير كافٍ.
2. احتفظ بحزمة العامل السابقة وبصماتها، وسجل bookmark حديثًا **قبل تصريح الترقية**. تحقق من توافره ضمن مدة الاحتفاظ للحساب؛ صحة صيغة bookmark لا تثبت توافره لدى المزود.
3. سجل مخطط المصدر وأسماء الترحيلات وبصمات الوثائق المحمية دون حفظ كلمات المرور أو الجلسات. لا تنشئ تصديرًا كاملًا إلى مجلد متزامن دون اعتماد المحتوى والوجهة.
4. استخدم مسار الترحيل المراجع في [دليل الترحيلات](migrations.md)، ثم تحقق من الحفظ والصلاحيات والقراءة بعد الحفظ والتعارضات.

## الرجوع المنسق للعامل والقاعدة

Time Travel يعيد قاعدة البيانات كاملة في مكانها، بما فيها الحسابات والصلاحيات وسياسات كلمات المرور والجلسات، ويلغي الاستعلامات الجارية ويفقد الحالة اللاحقة للنقطة المختارة. لا يضمن حفظ قيم الحسابات الحالية إن تغيرت منذ النقطة. مدة الاحتفاظ محدودة بحسب خطة Cloudflare. راجع [توثيق Cloudflare](https://developers.cloudflare.com/d1/reference/time-travel/) وتوافر النقطة قبل التنفيذ.

1. أوقف جميع الكتابات وأي استعادة أخرى وراجع ما سيفقد منذ bookmark. في خطة الرجوع من المخطط 7 إلى 5، أعد نشر الحزمة 5.2 المتحققة على `test` أولًا؛ سيرفض عاملها مخطط 7 حتى استعادة القاعدة. لا تعتبر إعادة نشر العامل وحدها رجوعًا للبيانات.
2. أنشئ سجل مراجعة بالحقول المغلقة الموضحة في `tools/d1/restore-review.example.json`: الحساب والقاعدة والنقطة ووقت التقاطها ومخططا المصدر والهدف وأسماء الترحيلات المتوقعة وغياب تصريح الترقية ومعرّف عملية UUID. المثال غير صالح للتنفيذ حتى تملأ القيم وتراجعها.
3. نفذ الأداة مرة واحدة، مستخدمًا **مسار أدلة جديدًا غير موجود**:

   ```text
   bash tools/d1/restore.sh bassam-db-preview --bookmark <reviewed-bookmark> --review <reviewed-record.json> --evidence-dir <new-metadata-directory> --yes
   ```

4. احتفظ بسجل العملية؛ يسجل النية قبل الطلب المدمر ونقطتي الحالة السابقة والعائدة عند استلامهما. عند المهلة أو الرد الملتبس، افحص الحالة قراءةً فقط. لا تعاود الطلب، ولا تستخدم مجلدًا جديدًا لإخفاء محاولة سابقة غير محسومة.
5. بعد ثبوت المخطط والسجل وغياب تصريح الترقية، تحقق من عمل حزمة العامل المتوافقة ومن الحسابات والصلاحيات والحفظ. العامل 7 المحفوظ يرفض ترقية قاعدة مستعادة مأهولة دون تصريح جديد؛ لا يتطلب الرجوع حذف الإصدار الجديد.

الأداة تمنع مشاركة مجلد الأدلة نفسه بين محاولتين، لكنها لا توفر قفلًا عامًا للقاعدة ضد مشغل آخر، ولا تجعل `--yes` موافقة إدارية. تتحقق من بقاء `authz_mode=enforce` قبل الاستعادة وبعدها؛ هذا فحص metadata وليس إثباتًا لكل محتوى البيانات أو الصلاحيات. فشل الفحص اللاحق يسجل الاستعادة غير متحققة ولا يؤدي إلى استعادة ثانية تلقائية. أزيلت واجهة `<dump.sql> --yes` القديمة لأنها كانت تسقط الجداول على طلبات منفصلة وتترك جداول أحدث غير موجودة في dump قديم.

## الإثبات والحدود

اختبارات `tests/unit/d1_tools.test.mjs` تثبت snapshot والتحقق والاستعادة **في SQLite محلي جديد** مع الحسابات والعلاقات والمراجعات. اختبارات أداة bookmark تستبدل النقل بمحاكاة وتختبر رفض الأهداف والتزامن والأخطاء؛ لا تعد تمرين استعادة سحابيًا.

في ترقية 30 أكتوبر 2026 حُفظت حزمة 5.2 وbookmark ما قبل التصريح، ولم تُنفذ استعادة Time Travel فعلية أو نسخة بيانات D1 كاملة محلية. سجلات الترقية والاختبارات في [دليل المشروع](../RISHAD266_PLAYBOOK.md). رفضت المراجعة التلقائية التصدير الكامل إلى OneDrive؛ لا تُعد تشغيله ضمن هذه التعليمات.

## سلامة النسخ المحلية

`python3 tools/d1/integrity.py <dump.sql | db.sqlite> --strict [--json out.json]` يفحص اتصال قطع KV وصحة JSON البنيوي والحسابات والمراجعات والجلسات وملكية الصور. طبّقه على نسخة محلية مصرح بها قبل الاعتماد عليها. هذا الفحص لا يثبت بذاته أن ترحيلًا أو استعادة سحابية قد نُفذت.
