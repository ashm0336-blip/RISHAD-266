## Preserve functioning accounts and existing owner-approved policies

- Employee, manager and platform administrator are different accounts and roles. A platform administrator is **not** the legacy bootstrap user `admin/admin`.
- Preserve login names, user IDs, role/department assignments, and existing password hashes when migrating a real account set to a new database. No silent password replacement, role escalation, or account deletion. Do not copy raw passwords to export files.
- Current source policy: login name is 10 digits; staff and general managers use 5 or 6 numeric digits; super and department administrators use 6 numeric digits with repeated/sequential PINs rejected. **Do not unilaterally change this policy.**
- Account provisioning from an empty database is an **explicit** authorized operation, never a public login side effect. Do not create a static user/password. A provisioning utility is not an account migration, and must not run on a database with existing identities.
- Existing system data might be disposable, but live identity records must be separately accounted for before any database reset. Password hashes and roles cannot be regenerated by guessing passwords.

## Acceptance checks for the future relational identity migration

1. A migrated employee can log in using their unchanged username/password and sees only their authorized screens.
2. A migrated platform administrator can log in using their unchanged credentials and keeps only their assigned administrative capabilities.
3. Invalid credentials fail. Empty database has no users and does not create any from `/api/login`.
4. Browser and Worker password policy tests agree by role; existing credentials do not trigger an unsolicited new policy.
5. A read-only source account inventory matches a relational target inventory by user ID, username, role, active/disabled state and department before any cutover.
6. All role and authentication actions use the server as the authority; no browser storage is a source of identity state.
7. No default account, legacy local authentication engine, or duplicate identity authority remains in the final build.
