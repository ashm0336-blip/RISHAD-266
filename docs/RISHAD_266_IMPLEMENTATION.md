# RISHAD 266 — حالة التنفيذ والتحقق

التاريخ: 29 أكتوبر 2026. نسخة عمل محلية؛ لم تعتمد للنشر على Production.

> سجل المرحلة4 تاريخي. المرجع الحالي هو [Playbook](RISHAD266_PLAYBOOK.md): ترحيل الإحصائيات والتنبيهات منفذ، والعهد والاستعادة المختلطة منفذان ومختبران محليًا في المصدر7. Preview ما زال5.2/المخطط5 وفق قراءة حية في30 أكتوبر؛ ترقية6/7 محجوبة بعزل النسخ القديمة. عبارات «غير مكتمل» وعقد الترحيل/الاستعادة أدناه تصف وقت إعداد هذه الوثيقة ولا تُستخدم بدل المصدر الحالي.

## المصدر والدمج

- دُمجت نسخة `RISHAD266_Phase4.zip` في المصدر المحلي، مع إبقاء التغييرات المحلية الأحدث وملف plugin manifest اللازم.
- بقي مجلد `.git` والربط بمستودع RISHAD-266؛ لم ينفذ Commit أو Push، ولم يعدّل مستودع RISHAD القديم.
- استُبعدت السجلات والملفات الحساسة، وتشمل `.gitignore` ملفات البيئة والمفاتيح وقواعد البيانات والنسخ الخاصة وملفات العمل المؤقتة.

## الحسابات والأمان

- لا ينشئ الدخول حسابًا افتراضيًا على قاعدة فارغة، ولا تعرض الواجهة بيانات دخول جاهزة.
- الحسابات والأدوار وسياسة كلمات المرور الأصلية محفوظة. تستمر قراءة البصمات القديمة الصحيحة وترقيتها عند الدخول الصحيح؛ لا تُستبدل كلمات المرور تلقائيًا.
- تأسيس أول مدير أداة صريحة خارج شاشة الدخول: `tools/provision_first_admin.mjs`، لقاعدة فارغة فقط، دون بيانات اعتماد ثابتة.
- هوية الجلسة من الخادم. يمنع غياب تهيئة الخادم التشغيل المحلي، وتفشل تغييرات الحساب عند انقطاع الاتصال أو غياب الإقرار الصحيح.
- يمنع تعارض تحديث كلمة المرور إصدار جلسة لبصمة أُلغيت، ويُرفض قبول نتيجة تحقق غير مدعومة كنجاح.
- حارس الترحيلات يرفض أسماء الترحيلات غير المعروفة وختم المخطط الأحدث أو غير الصالح قبل أي كتابة.

## المجال العلائقي المنجز: الإحصائيات اليومية

- `migrations/0004_daily_stats.sql` ينشئ جداول الأيام والأرقام وأقفال الأشهر والأيام، بمفاتيح وقيود صريحة. JSON محدود ببيانات الإسناد، ولا تُخزّن نسخة أعمال موازية في KV.
- `GET/POST /api/dstats` يقرأ ويكتب المجال مباشرةً مع الصلاحيات الحالية، ونطاق المسجد والحقول، وأقفال الاعتماد، ومراجعة CAS.
- صفوف المجال والمراجعة وسجل التدقيق ضمن دفعة D1 ذرية واحدة؛ لا يعلن العميل نجاح الحفظ قبل إقرار الخادم. يحتفظ بالمسودة عند الرفض أو فشل الشبكة.
- الاستيراد التاريخي والتصدير يقرآن المجال الجديد. يعيد ضبط المنصة حذف المجال داخل الدفعة نفسها.
- المفاتيح القديمة تُرفض في الحفظ العام قبل أي كتابة؛ القراءة العامة تشير إلى API المجال ولا تعيد البيانات القديمة.
- وجود بيانات إحصائيات KV في قاعدة قديمة يمنع الترقية بعلامة `KIVO_DSTATS_OFFLINE_CUTOVER_REQUIRED`. هذا **حارس لمنع فقد البيانات، وليس أداة لترحيل بيانات قائمة**.
- الاستعادة الشاملة التي تحتوي المجال الجديد مرفوضة قبل أي كتابة حتى يُنفذ عقد استعادة متعدد المجالات وذري. لا يُعد التصدير الحالي إثباتًا لدعم الاستعادة الشاملة.

- أزيل حسابا QA وجلساتهما وبياناتهما وملفات أسرارهما بعد الفحص السابق. لاحقًا أُنشئ حساب المالك الإداري عبر إدخال محلي خاص، ونجحت اختبارات دخوله وصلاحياته، ثم أكد المالك دخوله الفعلي بالواجهة. الحساب قائم ويجب الحفاظ عليه؛ لم تُحفظ بيانات دخوله في المصدر أو السجلات.

## الأدلة المحلية

- المجموعة الكاملة: 181 ملف اختبار، 1155 حالة؛ 1145 ناجحة، صفر إخفاق، و10 متخطاة لأسباب موروثة: أداتان انتقاليتان مفقودتان، ست مقارنات بلا وسوم Git، وحالتان لتوصيف ثغرة أصلحت سابقًا.
- اختبارات المجال المستقلة: 26 حالة ناجحة تشمل حفظ 13,006 حسابات صناعية وبصماتها وصلاحياتها، وفشل ترقية البيانات القديمة دون كتابة.
- المراجعة المستقلة أثبتت حدود الصلاحيات والحقول، وحذف المجال عند ضبط المنصة، وعدم الكتابة المزدوجة إلى KV.
- فُحصت بيانات الإحصائيات في تصدير Preview المصرح محليًا: ثلاثة أيام، قفلا شهر، قفلا يوم؛ نجحت مطابقة التحويل إلى صفوف وإعادتها دون تغيير التصدير.
- فحص الأسرار: 807 ملفات مرشحة للرفع و120 ملف بناء، دون اكتشاف. هذا فحص آلي ولا يمثل ضمانًا مطلقًا.
- فحص الحجم: جميع الحدود الـ16 ناجحة. ESLint: 323 ملاحظة مقابل خط أساس 325، دون أخطاء أو زيادة.
- جرى التحقق من مخططات المصدر وتطابق 23 ملفًا مولّدًا. أضيف توليد مخططات أجسام الطلبات إلى المولد حتى لا ينفصل عقد المصدر عن العامل.
- اختبار متصفح محلي على حزمة pk265 الفعلية مع SQLite/R2 في الذاكرة وحساب fixture صريح: نجح الدخول، وفتح الإحصائيات، وحفظ رقم مع إقرار نجاح من الخادم وبقائه بعد إعادة القراءة؛ ثم فُصل الخادم وبقيت المسودة دون رسالة نجاح. هذا ليس تشغيل Cloudflare الحقيقي.
- أدلة الاختبارات التفصيلية المحلية في `.cache/`؛ لا تُرفع تلك السجلات الخاصة إلى Git.

## الأعمال المتبقية

- التخزين العلائقي لا يشمل المنصة كاملةً بعد؛ الحسابات وبقية مجالات الأعمال ما زالت تستخدم KV/JSON في هذه المرحلة.
- يلزم تنفيذ استعادة شاملة ذرية، وأداة cutover معتمدة للبيانات القديمة، ثم نقل المجالات التالية دون الاحتفاظ بمخزن أعمال موازٍ.
- اختبارات Preview السابقة محدودة بالحالات الـ16 المذكورة؛ تأكد لاحقًا دخول المالك وفُحص تحميل17 مسارًا بحالة بيانات قليلة، مع إخفاق مسار المساعدة المباشر الذي عولج محليًا. هذا لا يمثل اختبار CRUD شاملًا لكل الصفحات. سجل الاستكمال والاختبارات الجديدة هو [Playbook](RISHAD266_PLAYBOOK.md)، ولا اعتماد Production قبل استكمال القبول.
- لا تتوفر وسوم Git التاريخية ضمن الأرشيف المستورد؛ بعض اختبارات المقارنة التاريخية غير قابلة للتشغيل من هذه النسخة.
